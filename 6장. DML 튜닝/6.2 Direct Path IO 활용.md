### 6.2 Direct Path I/O 활용

- DW, OLAP, 배치 프로그램은 주로 대량 데이터를 처리하므로 버퍼캐시 경유가 성능을 떨어뜨리기도 함
- 따라서, 버퍼캐시를 경유하지 않고 곧바로 데이터 블록을 읽고 쓸 수 있는 **Direct Path I/O** 기능 제공

<br>

- Direct Path Insert 방식이 빠른 이유
  - Freelist를 참조하지 않고, HWM 바깥 영역에 데이터를 순차적으로 입력
  - 블록을 버퍼캐시에서 탐색하지 않음
  - 버퍼캐시에 적재하지 않고, 데이터파일에 직접 기록
  - Undo 로깅을 최소화
  - Redo 로깅을 최소화하게 할 수 있음 ``` alter table t NOLOGGING; ```

<br>

- Direct Path Insert 사용 시 주의할 점
  - Exclusive 모드 TM Lock(테이블 락)이 걸린다
    - 커밋하기 전까지 다른 트랜잭션은 해당 테이블에 DML 수행 금지, 트랜잭션이 빈번할 때는 사용 불가
  - Freelist를 조회하지 않고 HWM 바깥에 입력하므로, 테이블 내부 공간 낭비 발생 

<br>

- 병렬 DML
  - UPDATE, DELETE 에서 Direct Path Write가 가능하도록 하는 방법
  - 병렬 DML 활성화 ``` alter session enable parallel dml ; ```
