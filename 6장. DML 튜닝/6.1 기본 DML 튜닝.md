### 6.1 기본 DML 튜닝

#### 6.1.1 DML 성능에 영향을 미치는 요소

1. 인덱스와 DML 성능
    - 테이블 : Freelist, 인덱스 : 수직적 탐색으로 데이터 입력
    - 인덱스를 하나라도 줄이면, TPS 성능 향상
    - UPDATE 시 인덱스 삭제 후 삽입, 총 2번 작업 발생 

<BR>

2. 무결성 제약과 DML 성능
   - DBMS에서 제약 설정하여 왼벽한 데이터 무결성 준수 
      - PK, FK 제약 : 실제 데이터 조회 (성능에 큰 영향)
      - Check, Not Null : 정의한 제약 조건을 준수하는지만 확인 (성능에 작은 영향)

<BR>

3. 조건절과 DML 성능
    - 조건절만 포함하는 기본적인 DML 문 = SELECT 문과 실행계획 동일
      - 인덱스 튜닝 원리 그대로 적용 가능 

<BR>

4. 서브쿼리와 DML 성능
    - 서브쿼리를 포함하는 DML 문 = SELECT 문과 실행계획 동일
      - 조인 튜닝 원리, 서브쿼리 조인 적용 가능 

<BR>

5. REDO 로깅과 DML 성능
    - 오라클은 데이터파일과 컨트롤 파일에 가해지는 모든 변경사항을 Redo 로그에 기록
    - DML을 수행할 때 마다 Redo 로그 생성 -> 따라서, Redo 로깅이 DML에 영향을 미침
    - Insert 작업에 대해 Redo 로깅 생략 기능 제공
  
<BR>

6. UNDO 로깅과 DML 성능
    - 트랜잭션을 롤백하여 과거 상태로 되돌리는데 사용
     - DML을 수행할 때 마다 UNDO 로그 생성 -> 따라서, UNDO 로깅이 DML에 영향을 미침
     - Undo 로그를 안남기는 방법은 없음

<BR>

7. LOCK과 DML 성능
    - LOCK : 동시성 제어를 위한 잠금, 해제
    - LOCK을 필요 이상으로 자주, 길게, 레벨을 높이면 DML 성능이 나빠짐
    - 그렇다고 너무 적게하면 데이터 품질이 나빠짐

<BR>

8. 커밋과 DML 성능
  - 커밋
    - 커밋과 DML은 별개로 실행하지만, **DML을 끝내려면 커밋까지 완료해야 하므로** 서로 밀접함
    - 커밋 과정
      - DML 실행, REDO 로그버퍼에 변경 기록
      - 데이터 변경
      - 커밋
      - 로그버퍼 -> 파일 저장
      - 변경된 블록 -> 데이터 파일 저장
    - Write Ahead Logging : 오라클은 데이터를 변경하기 전에 항상 로그부터 기록함
    - Log Force at Commit : '적어도 커밋시점에는' Redo 로그버퍼 내용을 로그파일에 기록한다


<BR>

#### 6.1.2 데이터베이스 Call과 성능

- 데이터베이스 Call
  - Parse Call : SQL 파싱과 최적화를 수행하는 단계
  - Execute Call : SQL 실행 단계
  - Fetch Call : 데이터를 읽어서 사용자에게 결과집합을 전송하는 과정 (SELECT문 ONLY)
- Call 발생 위치에 따른 분류
  - User Call : 네트워크를 경유해 dbms 외부로부터 반입되는 Call / 성능에 미치는 영향이 매우 큼
  - Recursive Call : dbms 내부에서 반입되는 call

<BR>

#### 6.1.3 Array Processing 활용

- Array Processing
  - 실무에서 One SQL을 작성하기 어려울 때, Array Processing 을 활용해 Call 부하를 줄일 수 있음
  - Array Size 크기만큼 묶어서 Call 하도록 조정

<BR>

#### 6.1.4 인덱스 및 제약 해제를 통한 대량 DML 튜닝

- 인덱스, 제약 해제를 통한 대량 DML 튜닝
  - 배치 프로그램(동시 트랜잭션 없이 대량 데이터 적재)에서는
    - 인덱스 해제
    - 무결성 제약 조건 해제로 성능 개선 효과 가능
  - 온라인 트랜잭션 처리 시스템에서는 이 기능 해제 불가

<BR>

#### 6.1.5 수정가능 조인 뷰 

- 수정가능 조인 뷰
  - 조인 뷰 : FROM 절에 두 개 이상의 테이블을 가진 뷰
  - 수정가능 조인 뷰 : 입력, 수정, 삭제가 허용되는 조인 뷰
    - 단, 1쪽 집합과 조인하는 M쪽 집합에만 입력, 수정, 삭제 허용 
- 키 보존 테이블 : 조인된 결과집합을 통해서도 중복 값 없이 Unique하게 식별이 가능한 테이블

<BR>

#### 6.1.6 MERGE 문 활용
- DW 시스템으로 데이터 적재하는 작업을 효과적으로 지원하기 위해 오라클 9i에서 MERGE 문 도입
- MERGE 문(UPSERT)
  - Source 테이블 기준으로 Target 테이블과 Left Outer 방식으로 조인
  - 조인 성공 : UPDATE
  - 조인 실패 : INSERT 
  - DELETE ++
