#### 1.1.1 구조적, 집합적, 선언적 질의 언어
SQL(Structured Query Language)

- 집합적

- 결과집합을 만드는 과정은 절차적(프로시저)

사용자 ->(sql)-> 옵티마이저 ->(실행계획)-> 프로시저

SQL 최적화란
- DBMS 내부에서 프로시저를 작성하고 컴파일해서 실행 가능한 상태로 만드는 전 과정

<BR>

- 절차형 SQL과의 비교
 - 사용 케이스
  - 조건에 따라 분기 처리가 복잡할 때
  - 에러 발생 시 예외처리가 필요할 때
  - 배치성 대량 데이터 가공 등

 
```SQL
//일반 SQL (선언적)
UPDATE 직원 SET 급여 = 급여 * 1.1 WHERE 부서 = '개발';

//위와 동일한 처리를 절차형으로 하면 👇
DECLARE
    v_급여  NUMBER;
    v_사번  VARCHAR2(10);
    
    CURSOR c1 IS
        SELECT 사번, 급여 FROM 직원 WHERE 부서 = '개발';
BEGIN
    OPEN c1;
    LOOP
        FETCH c1 INTO v_사번, v_급여;
        EXIT WHEN c1%NOTFOUND;
        
        UPDATE 직원
        SET 급여 = v_급여 * 1.1
        WHERE 사번 = v_사번;
        
    END LOOP;
    CLOSE c1;
    COMMIT;
END;
```

#### 1.1.2 SQL 최적화

 SQL 최적화 과정
 1) SQL 파싱
    - 파싱 트리 생성, 문법 및 의미상 오류 체크
 2) SQL 최적화
    - 옵티마이저가 담당
    - 미리 수집한 시스템 및 오브젝트 통계정보를 바탕으로 실행경로 선택 
 3) 로우 소스 생성
    - 로우 소스 생성기가 담당
    - 실행경로를 실제 실행 가능한 코드 또는 프로시저 형태로 포맷팅
